# Doot / Liza — Development Rules

1. Work only in the Doot repository and explicitly approved planning location.
2. Never modify ~/ai-agent-system or ~/doot-source-audit source-audit materials outside their intended scope.
3. Inspect git status, branch, HEAD and diffs before editing.
4. Preserve all pre-existing user changes and backup files.
5. Never reset, clean, force-push, rewrite published history or overwrite user work.
6. Confirm scope before deleting, renaming, migrating or changing production configuration.
7. Implement roadmap groups in dependency order; avoid unrelated changes.
8. After a group, run consolidated relevant tests, type checks, build, lint and diff review.
9. Record exact commands, outcomes, commit IDs and known failures in VERIFICATION_LOG.md.
10. Do not invent test results, API permissions, provider capabilities or deployment status.
11. Keep secrets out of source, logs, client bundles and documentation.
12. Use official integrations, least-privilege OAuth scopes and revocable credentials.
13. Require human approval for consequential external actions.
14. Maintain free-first cost controls, quotas and transparent paid-service dependencies.
15. Preserve Bangla, English and Banglish support.
16. Update project state and roadmap after every completed group.
